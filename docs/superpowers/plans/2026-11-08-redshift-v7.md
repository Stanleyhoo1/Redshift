# Redshift v7 Implementation Plan (master)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** Build the six v7 features from `docs/superpowers/specs/2026-11-08-redshift-v7-design.md` without
breaking anything that exists, committing after every finished piece.

**Architecture:** The spec covers six largely independent subsystems, so this master plan fixes order,
interfaces between features, gates and commit points. Each feature is then planned in detail just before it
is built (its own `docs/superpowers/plans/2026-11-08-v7-<feature>.md`, written against the code as it is at
that moment, TDD tasks with exact files, test code and commands), reviewed, implemented, reviewed again from
several angles, fixed and gated. Execution is orchestrated with the Workflow tool, one workflow per feature.

**Tech stack:** Python 3.12, MuJoCo 4.0.0, FastAPI, numpy, pytest (sim/); React 19, react-three-fiber 9,
drei 10, three 0.187, Vite 8, Playwright core (web/).

Interfaces fixed now so later steps can rely on them:

- `Config` gains (all default off / neutral in the dataclass): `mesas, canyon, dunes, boulder_fields, pits,
  geysers, ice_sheets, ground_detail, flora, wear: bool = False`, `wear_rate: float = 1.0`. Step A adds
  every one of these fields up front (unused until their step) so the settings schema and the setup screen
  are complete from the start; a later step only implements behaviour behind its flag.
- `config.SETTINGS` (step A) is the single source for keys, ranges and labels. Later steps never add a
  setting without adding it there.
- `world.World` gains `registry: dict[int, tuple[str, str]]` (geom id -> (cls, object_id)) in step B; steps
  C, D and E register their new geoms there.
- `camera.detect_objects(sim, rover_id, view="fpv", w=320, h=240, *, runner=None) -> dict` (step B) returns
  `{"t", "w", "h", "view", "detections": [{"cls", "label", "id", "box", "conf", "dist_m"}]}`. Step D calls it
  from the rules.
- The physics composer (step C2) is the only writer of wheel friction, wheel dof damping, body drag and
  actuator gain/bias/forcerange at run time: `sim.physics.compose(t)` reading per-rover and per-region
  causes. Step E registers tow neutral mode and wear damping through it.
- Fleet beliefs added as `fleet.stats()` keys only when their feature is on and non-empty: `ice_zones`,
  `geyser_zones`, `flora_zones`, `flora_seen`. (test_smoke pins FLEET_KEYS exactly with features off.)

## Per-feature procedure (each step A to F)

- [ ] **Plan.** Write `docs/superpowers/plans/2026-11-08-v7-<feature>.md` from the spec section, the ground
  rules above and the current code. Bite-sized TDD tasks: exact files (create/modify with line ranges),
  the failing test code, the command and expected failure, the implementation (code for anything
  non-obvious), the passing run, and the commit point. No placeholders.
- [ ] **Review the plan** from two angles in parallel: (1) spec coverage and internal consistency, (2)
  codebase reality (hooks exist where it says, nothing it does would break an existing test, budgets,
  determinism). Revise the plan with confirmed issues.
- [ ] **Implement** task by task with TDD. Run the targeted tests after each task, the gate before each
  commit. Commit at the plan's commit points.
- [ ] **Review the result** from three angles in parallel, each adversarial and evidence-based:
  (a) correctness and regressions against existing features (read the diff, run targeted tests and quick
  headless sims); (b) spec and project rules (no ground truth in rover logic, flags default off,
  determinism, protocol optional, no em dash, docs updated); (c) the running app (start sim + vite on the
  step's ports, drive it with Playwright, look at screenshots). Only one agent runs the full suite at a
  time (the brain-budget tests use the wall clock).
- [ ] **Fix** each confirmed finding (verify it first, do not fix on say-so), rerun the gate, commit
  "Fix review findings in <feature>". Repeat review and fix once more if anything high severity was found.
- [ ] **Final gate** by a fresh agent: full suite, web build, the step's own checks. Report pass/fail with
  the output tail.

## Step-specific notes (constraints the per-feature plans must honour)

### A. Launch settings
- Spec section 1. `AUTO_LAUNCH` default 0 means setup phase; tests never run the lifespan
  (`server.state.runner` is set directly), and web scripts call `POST /api/reset {"seed": n}` and expect a
  running sim: keep both working.
- Gravity-derived thresholds must be identical at 2 g (assert equality in a test).
- The Gemma prompts state gravity per request; the 2 g interpretation prompt stays at its current token
  count (test_gemma budget 400, today 397).
- Web: `SetupScreen.jsx`, `phase`/`config` in `simState`, `getConfig()`/`launch()` in `net/connection.js`
  using `postJson` so server error text shows; "New mission" next to Reset sim.
- Mock: settings object, `GET /api/config`, `POST /api/launch`, `MOCK_PROTOCOL >= 7`, `MOCK_PRELAUNCH`.

### G. Globe view (parallel, worktree)
- Spec section 5. Web only. Must not touch `sim/`. Keep edits to shared files (App.jsx, ViewControls.jsx,
  Scene.jsx, Legend.jsx, simState.js) minimal and local so the merge after step A is easy. Use the mock
  server for checks (`PORT=8102 node mock/mock-server.mjs`).
- Port ideas, not code, from `git show ros2_gazebo:web_ui/src/globe/*` (TypeScript there, JSX here).

### B. Camera detector
- Spec section 2. Segmentation via `mjRND_SEGMENT` and `mjRND_IDCOLOR` on the existing render thread; one
  render gives image, segmentation and depth. Detections deterministic per (sim time, rover). The detect
  endpoint returns the JPEG as base64 with the boxes so they always line up (no large response headers:
  nginx's default proxy buffer would reject them).

### C1 to C3. Terrain
- Spec section 3. Landform pass after `_make_heights`, before water; generalised no-trap; canyon ramps at
  most the tow limit (about 8 deg at 2 g) and at least 4 m wide.
- C2 must keep today's physics values exactly when only today's causes are active (the sand hazard tests
  pin exact behaviour). Ice mu about 0.05 and a separate `low_traction` detector (slip > 0.5 with low
  spin_load, near level); never trip the sand detector.
- C3 geysers: eruption state in `features` (resent on change); plume returns never reach the map, tracker
  or change detection.

### D. Flora
- Spec section 4. Group-2 stalk proxy (LiDAR + rules camera, no bumper), group-4 decor; neutral proxy
  colours (spot_targets must not fire on them). Identification through `camera.detect_objects` (throttled,
  `_hw_call`). Keep-out = plant radius + 4 m. Truth-side contact counter.

### E. Wear and towing
- Spec section 6. Equalities exist only when `wear` is on (default model unchanged). Release the hitch
  before every teleport. Never reverse while hitched. Never call `report_slope_stall` while towing. Tow
  limit `0.8 * asin(4*T/r / ((m1+m2)*g))`.

### F. Validation, docs, mock
- Spec section 7: `tests/test_v7_integration.py`, `web/scripts/v7-check.mjs`, docs (PROTOCOL v7 section and
  env tables, README, sim/README, sim/GEMMA, web/README), mock parity for the v7 features the UI renders.
- Restart the user's own servers on 8000 and 5173 with the new code at the end (`AUTO_LAUNCH=0`, so the
  setup screen shows first).
