# Launch Settings and Setup Screen Implementation Plan (v7 step A)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** Let the operator choose gravity, fleet size, sector size, world features, wear and speed on a
setup screen before the mission starts (spec section 1 of
`docs/superpowers/specs/2026-11-08-redshift-v7-design.md`), with every 2 g threshold derived from gravity so
nothing changes at 2 g.

**Architecture:** `config.SETTINGS` is the one table of launch settings (key, type, range, label, group,
help); `Config.from_settings()` validates request bodies against it, `Config.settings()` reports a config
back, `Config.from_env()` takes its clamps from it. The server builds the world at start but only runs it
after `POST /api/launch` (setup phase, `AUTO_LAUNCH=0` default); `GET /api/config` serves the table, the
current and default settings, presets and a climb/tow physics table; `restart_sim(cfg)` builds the new world
before stopping the old one. The web gets pure helpers (`lib/setup.js`), `phase`/`config` in `simState`,
`getConfig()`/`launch()` in `net/connection.js`, and `components/SetupScreen.jsx` (forced while the sim waits,
dismissible from a new "New mission" button). The mock mirrors all of it behind `MOCK_PROTOCOL >= 7`.

**Tech Stack:** Python 3.12, MuJoCo, FastAPI, numpy, pytest (sim/); React 19, Vite 8, Node 22 (`node:assert`),
Playwright core (web/).

# ====================================================================== v7 launch settings
# SETTINGS is the single source of the settings a mission can be launched with: keys, ranges, labels and
# help. GET /api/config sends it to the setup screen, Config.from_settings checks requests against it and
# Config.from_env takes its clamps from it. Later steps never add a setting anywhere else.
@dataclass(frozen=True)
class Setting:
    key: str                   # a Config field (wear stands for the wear and wear_rate pair)
    type: str                  # "int" | "float" | "bool" | "choice"
    label: str
    group: str                 # "planet" | "fleet" | "sector" | "features" | "wear" | "simulation"
    help: str                  # one line for the setup screen: what it is, what it does
    min: float | None = None   # int and float only
    max: float | None = None
    step: float | None = None
    unit: str = ""
    choices: tuple = ()        # choice only: ((value, label, help), ...)

    def to_json(self) -> dict:
        out = {"key": self.key, "type": self.type, "label": self.label, "group": self.group, "help": self.help}
        if self.type in ("int", "float"):
            out.update(min=self.min, max=self.max, step=self.step, unit=self.unit)
        if self.choices:
            out["choices"] = [{"value": v, "label": lab, "help": h} for v, lab, h in self.choices]
        return out

## Chunk 2: thresholds and Gemma's text follow the launch gravity

Background (measured with `scripts/climb_test.py` and the formula): the climb limit is set by motor torque,
`asin(4 * motor_torque / wheel_radius / (m * g))` with m = 22.5 kg (chassis 18, four 1 kg wheels, the 0.5 kg
axle bar in `world.py:118`): 21.25 deg at 2 g, 13.98 deg at 3 g (the ramp test fails at 14 deg at 3 g). At
1 g and below the motors could do more than the grip allows (the 1 g rover climbs 28 deg and tips at 32),
so the prediction is capped at 30 deg, the fleet's starting slope limit. Every derived threshold is
`min(today's value, climb - k)`, which is exactly today's value at 2 g because 21.25 - 2 > 15, 21.25 - 1 > 18
and 21.25 - 1 > 20.

The tow limit is defined here once, as `Config.tow_limit_deg`: the master plan's
`0.8 * asin(4*T/r / ((m1+m2)*g))` with the asin capped at the same 30 deg grip limit (uncapped, it would put
the tow limit above the single-rover climb below 0.73 g, e.g. 37.2 deg against a 30 deg climb at 0.5 g). It
equals the uncapped formula from 0.73 g up (8.35 deg at 2 g). Steps C1 (canyon ramps "at most the tow limit")
and E (tow paths, the rescuer announcement) must read `cfg.tow_limit_deg`, not re-derive the formula, so the
setup screen's number is the one the rovers use; PROTOCOL.md's Sim notes (Task 25) say so too.

# ====================================================================== gravity (v7)
# The slope thresholds below were tuned for 2 g. With a launch gravity they follow the rover's predicted
# climb limit instead, chosen so that each one is exactly its old value at 2 g.
ROVER_AXLE_MASS = 0.5        # world.py: the front axle bar (kg)
CLIMB_CAP_DEG = 30.0         # above this, grip and tipping limit the climb (climb_test at 1 g: 28 deg ok, tips at 32)
TOW_FACTOR = 0.8             # a tow train keeps this share of the two rovers' motor limit
TARGET_PATH_SLOPE = 15.0     # terrain.py: every target reachable from the lander without steeper ground
REACH_SLOPE = 18.0           # terrain.py: flood fill slope of the "no traps" checks for lakes and rivers
PASSABLE_SLOPE = 20.0        # hazards.py: steepest ground a placed hazard counts as drivable
SAND_SPIN_LOAD = 0.2         # rover.py: wheel load (share of the torque cap) that tells sand from free spin


def motor_climb_deg(gravity_g: float, mass: float, motor_torque: float, wheel_radius: float) -> float:
    """Steepest slope (deg) four wheel motors can hold `mass` on: asin(4 T / r / (m g)); 90 when they
    could lift it straight up."""
    ratio = 4.0 * motor_torque / wheel_radius / (mass * 9.81 * gravity_g)
    return math.degrees(math.asin(min(1.0, ratio)))

def _system_base(gravity_g: float = 2.0) -> str:
    """SYSTEM_BASE for one world's gravity (v7: the planner is shared across resets, so each request carries
    its own). Exactly SYSTEM_BASE at 2 g; at 1 g and below the world is "an unknown planet"."""
    gv = float(gravity_g)
    if round(gv, 1) == 2.0:
        return SYSTEM_BASE
    world = "super-Earth" if gv > 1.0 else "planet"
    return SYSTEM_BASE.replace("super-Earth (gravity 2 g,", f"{world} (gravity {round(gv, 2):g} g,", 1)


def _with_gravity(system: str, gravity_g: float) -> str:
    """A system prompt built on SYSTEM_BASE, restated for this gravity (unchanged at 2 g)."""
    if round(float(gravity_g), 1) == 2.0 or not system.startswith(SYSTEM_BASE):
        return system
    return _system_base(gravity_g) + system[len(SYSTEM_BASE):]

async def _restart(cfg: Config) -> None:
    """Build a world from cfg, then stop the old one, start the new one and re-init every client. The caller
    holds the reset lock. The new world is built first: if that fails (the exception propagates) the old
    world is untouched and keeps running. Order after the build, as before v7: stop the old world, THEN
    cancel. old.stop() joins the old sim thread and its advisor worker, which submit to the shared planner
    outside the sim lock; cancelling earlier would let a question they send in that window take Gemma's one
    slot ahead of the new world's first questions. The new world submits nothing until it steps."""
    new = await asyncio.to_thread(SimRunner, cfg)
    old = state.runner
    if old is not None:
        await asyncio.to_thread(old.stop)
    if state.planner is not None:
        state.planner.cancel()         # drop questions about the old world (nothing of it runs any more)
    # swap and re-init every client in one go (no await), so nobody sees the new sim's ticks first
    state.runner = new
    state.phase = "running"
    new.start()
    _reinit_clients()
    _log(f"new world: {_describe(cfg)}")


async def restart_sim(cfg: Config) -> None:
    """Replace the current world with a fresh one built from cfg, running at once."""
    async with _reset_lock():
        await _restart(cfg)

// Pure helpers for the setup screen (v7 launch settings, see PROTOCOL.md "Version 7 additions").
// No React or DOM in here, so scripts/setup-unit.mjs can check them in Node.

export const GROUP_TITLE = {
  planet: 'Planet',
  fleet: 'Fleet',
  sector: 'Sector',
  simulation: 'Simulation',
  features: 'Features',
  wear: 'Wear and repair',
}

// An older sim (no GET /api/config) can still be given a seed, through POST /api/reset.
export const SEED_FIELD = { key: 'seed', type: 'int', label: 'Seed', group: 'planet', help: 'Same seed, same terrain, targets and life.', min: 0, max: 2147483647, step: 1, unit: '' }

const G = 9.81
const INK = [232, 238, 245] // --ink
const RED = [255, 92, 70] // the red end of the Redshift wordmark

const trim = (v) => String(Number(Number(v).toFixed(2)))
const decimals = (n) => {
  const t = String(n)
  const i = t.indexOf('.')
  return i < 0 ? 0 : t.length - i - 1
}

// The server's fields by group, in the server's order. A group this client does not know lands in
// Simulation, so a setting added to the sim later still shows up.
export function fieldsByGroup(fields) {
  const out = {}
  for (const f of Array.isArray(fields) ? fields : []) {
    if (!f || typeof f.key !== 'string') continue
    const g = GROUP_TITLE[f.group] ? f.group : 'simulation'
    ;(out[g] ||= []).push(f)
  }
  return out
}

// Only the settings that differ from `current`: the launch body (keys left out stay as they are).
export function diffSettings(values, current) {
  const out = {}
  for (const [k, v] of Object.entries(values || {})) {
    const c = current?.[k]
    const same = typeof v === 'number' && typeof c === 'number' ? Math.abs(v - c) < 1e-9 : v === c
    if (!same) out[k] = v
  }
  return out
}

// A slider value on the field's step grid and inside its range, without float noise.
export function snap(field, v) {
  const lo = Number(field.min)
  const hi = Number(field.max)
  const step = Number(field.step) || 0
  let x = Math.min(hi, Math.max(lo, Number(v)))
  if (!Number.isFinite(x)) x = lo
  if (step > 0) {
    x = Math.min(hi, lo + Math.round((x - lo) / step) * step)
    x = Number(x.toFixed(Math.min(6, Math.max(decimals(step), decimals(lo)))))
  }
  return field.type === 'int' ? Math.round(x) : x
}

// The physics row (GET /api/config `physics`) nearest this gravity, or null.
export function physicsAt(rows, g) {
  let best = null
  for (const r of Array.isArray(rows) ? rows : []) {
    if (!Number.isFinite(r?.gravity_g)) continue
    if (!best || Math.abs(r.gravity_g - g) < Math.abs(best.gravity_g - g)) best = r
  }
  return best
}

export function presetName(presets, g) {
  const p = (Array.isArray(presets) ? presets : []).find((x) => Math.abs(x.value - g) < 1e-6)
  return p ? p.label : ''
}

export const metersPerSecond2 = (g) => (g * G).toFixed(1)

// Heavier gravity, heavier numeral: Archivo's width narrows, its weight grows and the ink shifts toward
// red, the gravitational redshift the planet is named after. t: 0 at the lightest gravity, 1 at the heaviest.
export function gravityLook(g, lo = 0.5, hi = 3) {
  const t = Math.min(1, Math.max(0, (g - lo) / (hi - lo)))
  const k = (0.55 * Math.max(0, t - 0.3)) / 0.7
  const rgb = INK.map((c, i) => Math.round(c + (RED[i] - c) * k))
  return { stretch: Math.round(122 - t * 50), weight: Math.round(380 + t * 420), color: `rgb(${rgb.join(', ')})` }
}

export function formatValue(field, v) {

  if (field?.key === 'gravity_g') return `${v.toFixed(1)} g`
  const unit = field?.unit || ''
  if (unit === 'x') return `${trim(v)}x real time`

}

  const s = String(text ?? '').trim()
  if (!/^\d{1,10}$/.test(s)) return null
  const n = Number(s)
  return n >= field.min && n <= field.max ? n : null
}

  if (!list.some((f) => f.key === 'gravity_g')) return Number.isFinite(values.seed) ? `Seed ${values.seed}.` : ''
  const n = Number(values.num_rovers) || 0

  }

}

function parseSettings(body) {
  if (!body || typeof body !== 'object' || Array.isArray(body)) return { errors: ['Body must be a JSON object like {"gravity_g": 1.5, "num_rovers": 4}'] }

    const f = FIELD[key]

    } else if (f.type === 'bool') {

    } else if (f.type === 'choice') {

    } else if (typeof v !== 'number') {

    } else if (!Number.isFinite(v)) {

    } else if (f.type === 'int' && !Number.isInteger(v)) {

Design brief (from the frontend-design pass, binding for this chunk): the screen belongs to the existing
mission-control look (`styles.css` tokens: `--void`, `--panel`, `--line`, `--ink`, `--ink-2`, `--ink-3`,

// The setup screen (v7, PROTOCOL.md "Version 7 additions"). Forced while the sim waits in its setup phase:
// no close button, Esc and the backdrop do nothing, and App closes it when the launched world's init
// arrives. Opened from "New mission" it can be closed, and launching replaces the running mission.
// An older sim (no GET /api/config) only gets the seed, through POST /api/reset.

const WAIT_MS = 20000 // after the sim said yes, how long to wait for the new world's init
const SIDE_GROUPS = ['fleet', 'sector', 'simulation']
const close = () => appStore.patch({ modal: null })
const noop = () => {}

export function SetupScreen({ forced = false }) {

  const liveSeed = useSim((s) => s.config?.seed ?? s.world?.seed)

  useEffect(() => {
    let live = true

      .then((cfg) => {

        setServer(got)
        setValues({ ...got.current })
        setSeedText(String(got.current.seed ?? ''))
      })
      .catch((err) => {
        if (live) setLoadError(err?.message || 'Could not read the settings')
      })

      live = false
    }
  }, [attempt])

    if (busy || !server || !values || !seedOk) return
    setError('')
    startGen.current = gen

    try {
      if (server.legacy) await resetSim(values.seed)
      else await launch(diffSettings(values, server.current))
    } catch (err) {
      setBusy(false)
      setError(err?.message || 'Launch refused')
    }
  }

  const title = forced ? 'Plan the landing' : 'New mission'
  const lede = forced
    ? 'The fleet waits on the lander pad. Nothing moves until you launch.'
    : 'Launching ends the current mission and lands the fleet on a new world with these settings.'
  const ready = !!server && !!values && !loadError
  const seedInput = <SeedField field={seedField} text={seedText} onText={typeSeed} onNew={() => typeSeed(String(randomSeed()))} onEnter={go} />

          {loadError}

        <p className="su-help">Check that the sim is running, then try again.</p>
        <button type="button" className="btn" onClick={() => setAttempt((n) => n + 1)}>
          Try again
        </button>
      </div>
    )
  } else if (!ready) {
    body = (
      <div className="su-body su-state">
        <p className="su-help" role="status">
          Reading the sim's settings...
        </p>
      </div>
    )
  } else if (server.legacy) {
    body = (

        {seedInput}
        <p className="su-note">This sim only lets you choose the seed. Gravity, fleet, sector and features come from its environment variables.</p>
      </div>
    )
  } else {
    const groups = fieldsByGroup(server.fields)
    const grav = server.fields.find((f) => f.key === 'gravity_g')
    const planetRest = (groups.planet || []).filter((f) => f.key !== 'gravity_g' && f.key !== 'seed')
    const field = (f) => <Field key={f.key} field={f} value={values[f.key]} onChange={(v) => set(f.key, v)} />
    body = (
      <div className="su-body">
        <div className="su-planet">
          {grav && <GravityHero field={grav} value={values.gravity_g} onChange={(v) => set('gravity_g', v)} presets={server.presets?.gravity_g} physics={server.physics} />}
          {seedInput}
          {planetRest.map(field)}
        </div>
        <div className="su-rest">
          <div className="su-trio">
            {SIDE_GROUPS.filter((g) => groups[g]).map((g) => (
              <section key={g} className="su-sec" aria-labelledby={`su-g-${g}`}>
                <h3 className="su-sec-title" id={`su-g-${g}`}>
                  {GROUP_TITLE[g]}
                </h3>
                {groups[g].map(field)}
              </section>
            ))}
          </div>
          {groups.features && <FeatureGrid fields={groups.features} values={values} set={set} setAll={setAll} />}
          {groups.wear && (
            <section className="su-sec" aria-labelledby="su-g-wear">
              <h3 className="su-sec-title" id="su-g-wear">
                {GROUP_TITLE.wear}
              </h3>
              {groups.wear.map(field)}
            </section>
          )}
        </div>
      </div>
    )
  }

  return (
    <Modal label={title} onClose={forced ? noop : close} className={`su${forced ? ' su-forced' : ''}`}>
      <header className="su-head">
        <div className="su-titles">
          <h2 className="su-title">{title}</h2>

        </div>

        <div className="su-foot-text">

              {error}
            </p>
          )}
          <p className="su-summary">{ready ? summary(values, server.fields) : ''}</p>
        </div>
        <button type="button" className="su-launch" disabled={!ready || busy || !seedOk} onClick={go}>
          {busy ? 'Launching...' : 'Launch'}
        </button>
      </footer>
    </Modal>
  )
}

function Field({ field, value, onChange }) {
  if (field.key === 'num_rovers') return <Stepper field={field} value={value} onChange={onChange} />
  if (field.type === 'bool') return <ToggleField field={field} value={value} onChange={onChange} />
  if (field.type === 'choice') return <ChoiceField field={field} value={value} onChange={onChange} />
  if (field.type === 'int' || field.type === 'float') return <RangeField field={field} value={value} onChange={onChange} />
  return null
}

const fillOf = (field, v) => `${(((Number(v) - field.min) / (field.max - field.min)) * 100).toFixed(1)}%`

// The steepest climb (cyan) and the towing limit (amber dashes) at this gravity, drawn to scale.
const FIG_O = [34, 104]
const FIG_L = 196
const at = (deg, len) => [FIG_O[0] + len * Math.cos((deg * Math.PI) / 180), FIG_O[1] - len * Math.sin((deg * Math.PI) / 180)]
const xy = (p) => `${p[0].toFixed(1)} ${p[1].toFixed(1)}`

function SlopeFigure({ row }) {
  const climb = Number(row.climb_deg)
  const tow = Number(row.tow_deg)
  const [ox, oy] = FIG_O
  const top = at(climb, FIG_L)
  const towTop = at(tow, FIG_L)
  return (
    <figure className="su-fig">
      <svg viewBox="0 0 260 120" role="img" aria-label={`Steepest climb ${climb.toFixed(1)} degrees. Towing ${tow.toFixed(1)} degrees.`}>
        <path className="su-fig-wedge" d={`M${ox} ${oy}L${ox + FIG_L} ${oy}A${FIG_L} ${FIG_L} 0 0 0 ${xy(top)}Z`} />
        <path className="su-fig-ground" d={`M${ox - 22} ${oy}H${ox + FIG_L + 18}`} />
        <path className="su-fig-arc" d={`M${ox + 46} ${oy}A46 46 0 0 0 ${xy(at(climb, 46))}`} />
        <path className="su-fig-tow" d={`M${ox} ${oy}L${xy(towTop)}`} />
        <path className="su-fig-climb" d={`M${ox} ${oy}L${xy(top)}`} />
        <g className="su-fig-rover" transform={`translate(${xy(at(climb, FIG_L * 0.55))}) rotate(${(-climb).toFixed(1)})`}>
          <rect x="-10" y="-10" width="20" height="6.5" rx="1.5" />
          <circle cx="-6.5" cy="-2.6" r="2.6" />
          <circle cx="6.5" cy="-2.6" r="2.6" />
        </g>
        <text x={(top[0] + 6).toFixed(1)} y={(top[1] + 4).toFixed(1)}>
          {climb.toFixed(1)}°
        </text>
        <text className="su-fig-tow-label" x={(towTop[0] + 6).toFixed(1)} y={(towTop[1] + 4).toFixed(1)}>
          {tow.toFixed(1)}°
        </text>
      </svg>
      <figcaption className="su-fig-cap">
        <span className="su-key su-key-climb">
          Steepest climb {climb.toFixed(1)}°{row.grip_limited ? ' (grip limits it here, not the motors)' : ''}
        </span>
        <span className="su-key su-key-tow">Towing a broken rover {tow.toFixed(1)}°</span>
        <span className="su-fig-note">Predicted from motor torque and rover mass. The fleet still learns its real limit on the slopes it drives.</span>
      </figcaption>
    </figure>
  )
}

function FeatureGrid({ fields, values, set, setAll }) {
  const bools = fields.filter((f) => f.type === 'bool')
  const others = fields.filter((f) => f.type !== 'bool')

- `fields`: the table above as data, in order, so a client can draw the form from it (a setting added later

### `POST /api/launch`

Body: any launch settings, for example `{"gravity_g": 1.0, "num_rovers": 4}`. Keys left out keep the values
of the world the sim holds; `{}` launches it as built.

- From the setup phase with nothing changed, the built world starts. Otherwise (changed settings, or a
  launch while running, which starts a new mission) a new world is built first, then the old one stops.
- `200 {"ok": true, "phase": "running", "config": {...}}`; every client gets a fresh `init`.
- `400 {"ok": false, "error": "gravity_g must be between 0.5 and 3 g; water must be true or false", "errors": ["gravity_g must be between 0.5 and 3 g", "water must be true or false"]}`:
  every problem found, and nothing changes. The texts: `unknown setting 'warp' (use one of gravity_g, seed, ...)`,
  `<key> must be true or false`, `<key> must be one of off, normal, harsh`, `<key> must be a number`,
  `<key> must be a finite number`, `<key> must be a whole number`, `<key> must be between <min> and <max> <unit>`,
  `<key> must be in steps of <step> <unit>`, `Body must be a JSON object like {"gravity_g": 1.5, "num_rovers": 4}`.
- `500 {"ok": false, "error": "Could not build the new world: ..."}`: the world the sim held is untouched
  (and keeps running if it was). `503` before the sim has a world.

### `POST /api/reset` additions

- Takes any launch setting next to `seed`, for example `{"seed": 7, "gravity_g": 1.5}`. Keys left out keep
  the current world's values (so "Reset sim" keeps gravity, fleet and features and only changes the seed).
- `seed` keeps its old leniency (`"8"` and `7.9` work, an empty body keeps the seed, a body that is not an
  object is ignored) but must be 0 to 2147483647: otherwise 400 (`seed must be between 0 and 2147483647`,
  `seed must be an integer`). Bad settings give 400 as for `POST /api/launch`; a failed build gives 500 and
  the old world keeps running.
- Works from the setup phase too: the mission starts at once.
- Returns `{"ok": true, "seed": 7, "config": {...}}`.

### Sim notes

- The slope thresholds tuned for 2 g follow the launch gravity. The predicted climb limit is
  `asin(4 T / r / (m g))` with T = 7.2 N m per wheel motor, r = 0.18 m and m = 22.5 kg, capped at 30 deg
  where grip and tipping take over: 21.3 deg at 2 g, 14.0 at 3 g, 30 at 1 g. From it: target paths at most
  `min(15, climb - 2)` deg, the lake and river no-trap flood `min(18, climb - 1)`, hazard placement
  `min(20, climb - 1)`, the floor of the learned slope limit `min(12, climb - 2)`, the sand wheel load
  `0.2 * min(1, g / 2)`, and the towing limit `0.8 * min(30, climb for twice the mass)`. At 2 g every one is
  exactly its old value.
- The towing limit is `Config.tow_limit_deg`, the one place it is computed: the formula of the wear and
  towing design, `0.8 * asin(4 T / r / ((m1 + m2) g))`, with the asin capped at the same 30 deg grip limit as
  a single rover (a tow train never climbs steeper than one rover alone). The two agree from about 0.73 g up
  (8.4 deg at 2 g, 17.0 at 1 g); below that the cap holds it at 24 deg. Later steps (canyon ramps, tow paths
  and their announcements) read `cfg.tow_limit_deg` rather than computing their own, so the setup screen,
  `physics` and the rovers always quote the same number.
- Gemma's prompts state each request's gravity: at 2 g the text is byte for byte as before ("super-Earth
  (gravity 2 g, ..."); at 1 g and below the world is "an unknown planet (gravity 1 g, ...". Operator commands
  and chat answers name the world without a number ("a super-Earth", at 1 g and below "a planet"), since
  they may only quote their own inputs.
- `Config.from_env` clamps `SEED`, `NUM_ROVERS`, `SIM_SPEED`, `MAP_SIZE` and `GRAVITY_G` to the table's
  ranges. The feature env vars are on when unset; set, they are on only for `1`, `true`, `yes` or `on`. An
  unknown `WEAR` gives normal.
